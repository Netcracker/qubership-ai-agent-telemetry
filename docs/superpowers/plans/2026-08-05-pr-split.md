# Metrics and maintenance PR split implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild PR #26 as a metrics-only branch and create a stacked maintenance branch without losing reviewed work.

**Architecture:** Protect the mixed source and final planning state with signed tags. Build an independent expected
metrics tree, reconstruct the actual metrics branch through a separate path, and require exact tree and blob equality.
Apply the remaining tree delta onto a branch whose parent is the cleaned metrics head.

**Tech Stack:** Git worktrees, signed Git tags and commits, POSIX patch files, SHA-256, GitHub CLI.

## Global constraints

- Never connect to the production server.
- Push branches only to `im`; use `--force-with-lease` for the rewritten PR #26 branch.
- Preserve `backup/remote-codex-metrics-mixed-source-20260805` at `de75b951e6829bc948dd81d4fa7ca53ff696d1bd`.
- Create `backup/remote-codex-metrics-pre-rewrite-20260805` at the final planning commit before changing branch history.
- Use `2000143a0dae2aec549cf08a7a677a48f3245878` as the full PR base and
  `b15c3a8d6653b70afa12bf63cabd4a282cac2f75` as the late-change boundary.
- The late metrics diff has exactly ten paths; the full metrics PR diff has exactly 30 paths.
- Do not publish either branch until its diff manifest, expected tree, tests, and current review threads pass.
